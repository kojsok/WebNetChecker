## 🔴 Критично (1)

### 🔴 1. Обход rate-limit через подмену `X-Forwarded-For` `#wnc-xff-bypass`

- **Файл:** `src/lib/rate-limit.ts:51-59` (`getClientKey`), используется в `src/app/api/scan/route.ts:33`
- **Суть простыми словами:** сервер определяет «кто сканирует» по заголовку `X-Forwarded-For`, а этот заголовок присылает сам клиент. Любой может писать в него что угодно — как подписать письмо чужим обратным адресом.
- **Как это выглядит на практике (воспроизведено):** исчерпали лимит 10 сканов/мин → получили 429. Добавили к запросу `X-Forwarded-For: 10.0.0.1` → снова 200. Меняя IP в заголовке, можно сканировать **без ограничений вообще**.
- **Чем это грозит:** `/api/scan` заставляет ваш сервер делать сетевые запросы к любым публичным URL. Без лимита приложение превращается в бесплатную публичную «пушку» для сканирования/рекогносцировки третьих сайтов (у каждого сайта ваш сервер появится в логах как источник), и можно выжечь исходящие сокеты/трафик сервера. SSRF-защита от внутренностей сети стоит крепко, но именно rate limit — единственный барьер от «бесплатности» этого инструмента для чужих.
- **Важно:** за Vercel/облаком с прокси платформа перезаписывает заголовок — там риск ниже. При прямом деплое `next start` (VPS) — полностью открыто.
- **Фикс:** брать IP из доверенного источника (платформенный заголовок, socket address), брать **последнее** значение из цепочки XFF только за доверенным прокси; добавить глобальный резервный бакет (по образцу `#r7-login-xff` из LLMRouter) + Redis-лимитер для распределённого деплоя (README уже намечает).

### 🟡 5. Каждая карточка подписана на весь store `#wnc-card-store`
- **Файл:** `src/components/ServiceCard.tsx:59` — `const { history, togglePin, targets } = useScanStore();`
- **Простыми словами:** вызов `useScanStore()` без селектора подписывает карточку на **любое** изменение стора. Во время скана стор обновляется на каждый пришедший результат (60 целей = 60 обновлений) → все карточки перерисовываются 60 раз за скан (60 карточек × 60 событий ≈ 3600 лишних рендеров).
- **Пример воздействия:** на каталоге 200 целей (максимум по умолчанию) скан с автособновлением каждые 30 с превращается в постоянную перерисовку всей сетки — на слабых машинах/телефонах интерфейс начинает «лагать» именно во время скана.
- **Правило:** react-best-practices `rerender-defer-reads`, `rerender-derived-state` (остальные компоненты делают это правильно — только ServiceCard нарушает).
- **Фикс:** три узких селектора: `useScanStore(s => s.history[url])`, `useScanStore(s => s.targets.find(...)...)` через Map, `useScanStore(s => s.togglePin)`.

### 🟡 6. «Перепроверить» и «Сравнение» убивают идущий скан; автообновление не ждёт завершения `#wnc-retry-abort`
- **Файлы:** `src/hooks/useScan.ts:16` (`controllerRef.current?.abort()`), `src/app/page.tsx:102-108` (retryOne), `src/components/ComparisonView.tsx:112-116`, `src/hooks/useAutoRefresh.ts:15-19` (нет guard на `isScanning`)
- **Простыми словами:** у приложения один общий AbortController. Кнопка «↻» на карточке запускает новый скан → **прерывает** текущий общий скан на середине. Прогресс-бар обнуляется. Автообновление (30 с) тоже перезапускает скан, не дождавшись предыдущего: каталог из 60 целей при таймауте 3 с × 2 попытки и конкурентности 10 может длиться дольше 30 с → сканы будут вечно обрываться на 60–70 %.
- **Пример воздействия:** нажали «перепроверить» один сервис во время большого скана → потеряли прогресс всего скана; включили автообновление 30 с на медленных целях → вечные незавершённые сканы + сгорание лимита.
- **Фикс:** guard `isScanning` в автообновлении (пропускать тик); retry/compare — отдельный лёгкий контроллер, не задевающий общий скан.

### 🟡 7. История пишется опросом каждые 500 мс и смешивает результаты разных сканов `#wnc-history-poll`

- **Фикс:** пушить историю в момент события `done` (в useScan/applyEvent), скоуп результатов — текущий скан.

## ✅ Удачные решения (по правилу «хвалить коротко»)

1. **SSRF-защита на connection-time** (`ssrf-guard.ts`): валидация IP внутри DNS-lookup undici-агента закрывает DNS-rebinding принципиально, а не эвристикой. Рантайм-тест подтвердил: `127.0.0.1`, `localhost` → blocked; fail-closed на непарсируемых IPv6.
2. **`normalizeUrl`** — discriminated union + отказ от credentials/контрольных символов; чисто и тестируемо (14 unit-тестов).
3. **Ядро под тестами** — pool/classify/ssrf/normalize покрыты; 45/45 зелёные; пул конкурентности корректно работает с прерыванием.
4. **Security headers** (`next.config.ts`): CSP без внешних источников, `frame-ancestors 'none'`, HSTS, `poweredByHeader: false`.
5. **`prefers-reduced-motion`** полностью учтён в CSS; семантика и aria-лейблы в большинстве компонентов; статусы подписаны словами, не только цветом.
6. **Инфраструктурные интерфейсы** (`RateLimiter`, `ScanCache`) — задел под Redis/БД из README честный.
7. **NDJSON-стриминг** с `x-accel-buffering: no` и `no-store` — правильный транспорт для живых результатов.

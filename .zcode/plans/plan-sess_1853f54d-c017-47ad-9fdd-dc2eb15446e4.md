Решения согласованы: DEPLOY.md — **Vercel + Docker/VPS**; SCAN_API_KEY — **прокси-роут `/api/scan/run`**; тег-фильтр — **добавляем в UI**; **git init** перед правками. Порядок: пакеты → фиксы по спринтам → скриншоты/README/DEPLOY → Obsidian → финальные гейты. Скриншоты делаем ПОСЛЕ фиксов UI, чтобы они показывали исправленный интерфейс.

## Этап 0 — Базовая линия (~15 мин)
1. `git init`, стартовый коммит «baseline: аудит 2026-10-03» (сейчас код чистый — идеальная точка отката). Убрать мусор из коммита: `.next_old/` удалить (и из диска), `.next*/`, `tsconfig.tsbuildinfo` — в `.gitignore`.
2. Обновление пакетов: `npm update` внутри диапазонов (возьмёт **next 16.3.8 — security-патчи 16.3.6+16.3.8**, zod 4.6.5, undici 8.11.2, vitest 5.0.3, @playwright/test 1.63.0, TS/eslint — последние 5.x/9.x) + `lucide-react@1.50.0` (мажор 0.x→1.x; все импортированные иконки проверит typecheck). **Не берём мажоры** TypeScript 7.0 и ESLint 10 — Next 16.3 валидирован под 5.x/9.x, риск неоправдан.
3. Сразу же фикс `#wnc-eslint-noise`: `.next_old/**`, `.omo/**` в eslint ignores — гейт линта оживёт для всех следующих этапов.
4. Гейты: `typecheck / lint / test / build` → коммит «chore: upgrade deps».

## Этап 1 — Спринт А: безопасность и гейты (~1.5 ч, коммит на каждый фикс)
1. **🔴 `#wnc-xff-bypass`** — `getClientKey`: env `TRUST_PROXY` (по умолчанию `0`): при `1` (за nginx/Vercel) берём **последнее** значение XFF-цепочки, при `0` — XFF не доверенный. В обоих случаях добавляем **глобальный резервный бакет** `RATE_LIMIT_GLOBAL` (дефолт 60/мин): подмена заголовков вращает пер-ключи, но глобальный кап не обойти. Unit-тесты на оба бакета + smoke-curl из аудита (11-й запрос с разными XFF → 429).
2. **`#wnc-key-ui-gap`** — рефактор: логика POST `/api/scan` переезжает в `src/lib/checker/scan-handler.ts`; новый роут `/api/scan/run` (same-origin проверка + ключ подставляется серверно, не покидает сервер); `useScan` переключается на `/api/scan/run`. UI работает при любой конфигурации ключа.
3. **`#wnc-latest-leak`** — `Cache-Control: no-store` на `/latest`; в глобальный кэш пишем **только результаты seed-целей** (фильтр по множеству `SEED_TARGETS` при `cache.set`): кастомные цели больше не утекают между посетителями.
4. **`#wnc-green-batch`** — `timingSafeEqual` для сравнения ключа; флаг `closed` из `cancel()` перед `enqueue` в стриме; `AbortError` не ретраится как timeout; замер latency до drain тела.
5. **`#wnc-env-docs-drift`** — `opengraph-image.tsx` → `runtime = "nodejs"`; README/env.example: `SCAN_MAX_TARGETS=200` (код оставляем); «no any» станет правдой; в «Возможности» — импорт списка целей.
6. Гейты → коммит.

## Этап 2 — Спринт Б: целостность UI (~2 ч)
1. **`#wnc-retry-abort`** — guard `isScanning` в `useAutoRefresh` (тик пропускается пока идёт скан); retry/сравнение — изолированный контроллер, не трогающий общий скан и общий прогресс.
2. **`#wnc-history-poll`** — убрать опрос 500 мс; `beginScan` снапшотит URL-ы скана, история пишется один раз по завершении потока со скоупом этого скана.
3. **`#wnc-tagfilter-dep`** — `tagFilter` в deps `useMemo`; селект тегов в `FilterBar` (уникальные теги из целей). 
4. **`#wnc-rejected-lost`** — событие `{ type: "rejected", items }` в `ScanEvent` + панель «Отклонено N: url — причина»; заодно отображение `done.aborted` («скан прерван»).
5. **`#wnc-card-store`** — узкие селекторы в `ServiceCard` (history[url], togglePin, цель через Map) — убирает ~3600 лишних рендеров за скан.
6. Unit/e2e-тесты на изменённое; гейты → коммит.

1. **`#wnc-a11y-dialog`** — Escape + ловушка фокуса + блокировка скролла в диалоге; закрытие меню по Escape/клику-вне; тултип ошибки с фокусом; динамический aria-label pin («Открепить»).

3. **`#wnc-terminal-ok`** — единая `terminalLine` (лейбл статуса вместо «OK»), удалить дубль из стора; **`#wnc-terminal-growth`** — кап лога 500 строк + `content-visibility`.
4. **`#wnc-progress-initial`** — стейт «Ожидание запуска» до первого скана.
5. **`#wnc-seed-dead`** — удалить мёртвый `/api/seed` (+ README/архитектура); **`#wnc-bulk-limit`** — кап импорта = `NEXT_PUBLIC_SCAN_MAX_TARGETS` (дефолт 200) + валидация до добавления.
